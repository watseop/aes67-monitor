# 로드맵

## 진행 순서
예약 개발 작업은 아래 순서대로 한 번에 항목 하나씩 진행한다. 각 항목의 상세 설명은 해당 마일스톤 섹션에 있다. 이 순서가 마일스톤 번호나 섹션 순서보다 우선한다.
1. **M1 패키징**: 맥 아이콘 `.icns` 교체, `.dmg` 빌드, Gatekeeper 확인
2. **M2 채널별 레벨 미터**: 신호 없음(무음) 채널이 화면에서 바로 보이게 한다. 실기 확인에서 소스에 신호가 없어 원인 찾는 데 시간이 걸린 것이 계기다. (완료: PR #10 머지 후 반영)
3. **M2 스트림 그룹화 + 다중 재생·레벨 미터링**: 12채널(7.1.4)처럼 한 소스가 여러 스트림으로 나뉘는 경우를 한 번에 본다.
4. **M1 Electron 업그레이드**: 네이티브 모듈(Audify) 재빌드가 걸려 위험도가 높으므로 기능 작업 뒤에 한 단계씩 진행한다.
5. **M2 나머지**: 패킷 손실·지터·시퀀스 점프 통계, 패킷 길이 불일치 드롭 카운터, PTP 상태 표시

위 5개를 마치면 다음 순서는 사용자와 먼저 정한다.

## 최종 목표 (2026-11-11 사용자 지시)
Dante Controller와 Dante Virtual Soundcard의 기능을 합친 **AES67 Controller 겸 Virtual Soundcard**. 지금의 모니터링(M2)은 그 기반이다.
- 매트릭스 형태의 UI: Dante Controller의 라우팅 매트릭스처럼 어떤 스트림·채널이 어디로 연결돼 있는지 한눈에 볼 수 있어야 한다. 같은 소스의 여러 스트림은 하나로 묶어 보여 주며, 채널이 많은 큰 그룹(예: 136채널)도 하나로 묶는다(사용자 결정).
- 매트릭스의 구체적인 설계는 M3 Return(가상 사운드카드 방식) 결정 이후 정한다. 미정: 행·열 구성(송신 스트림·채널 / 수신 가상 장치 채널), 교차점 동작. AES67에는 Dante 같은 구독 프로토콜이 없으므로, 교차점은 멀티캐스트 수신과 채널 매핑으로 구현해야 한다.
- 위 두 항목은 방향 기록이며 구현 순서는 "진행 순서"를 따른다.

  - 진행: (A) 그룹 표시 UI는 PR #12로 머지되었고 사용자가 맥에서 확인했다(2026-11-11). (B)는 이 브랜치(`claude/group-monitoring`)에서 구현했으나 맥 확인 전이다. (C)는 미착수.
  - 그룹 판정 초안: 같은 장치 주소, 이름 끝 `-숫자`를 뗀 앞부분이 같음, 코덱·샘플레이트·패킷 시간이 같음, 채널 범위가 끊김 없이 이어짐(다음 시작 번호 = 이전 시작 번호 + 이전 채널 수). 맞는 경우만 묶고 나머지는 개별 스트림으로 둔다.
  - (C) 출력 모드 요구사항(2026-11-11 사용자 지시): 출력 장치가 다중 채널 환경이면 다중 채널로, 아니면 스테레오로, 아니면 모노로 들을 수 있고, 사용자가 모드를 선택할 수 있어야 한다. 최종 출력이 다중 채널이면 스트림(그룹)의 채널을 출력 채널에 순서대로 매핑해 다중 채널로 재생한다. 선택 가능한 모드는 선택한 출력 장치의 출력 채널 수(`outputChannels`)로 판단한다. 모노 모드는 스트림(그룹)의 모든 채널을 다운믹스(합산)해 좌우 양쪽으로 보낸다(2026-11-11 사용자 결정). 현재는 스테레오 출력 고정이다.
